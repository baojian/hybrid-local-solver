# Exact rational prototype: verification and limitations

Files: `local_safe_solver.py`, `test_local_safe_solver.py`, `solver_verification.json` in this research directory. The implementation is a deterministic baseline, not a proof of the conjectured work bound.

The numerical system is `H y = alpha e_v - alpha rho d`, where `H=aD-cA` and `x_i=sqrt(d_i)y_i`. Diagonal-preconditioned CG is the degree-coordinate equivalent of CG on the normalized principal matrix. Its exact residual certificate is `eta=max_i |r_i|/d_i`, the lower envelope is `max(0,y_i-eta/alpha)`, and the stopping comparison is the square-root-free rational inequality `eta² <= alpha³ rho epsilon/2`. The final direct certificate is the squared minimum subgradient norm divided by `2alpha`, computed as degree-weighted residual squares. Every boundary contribution is evaluated from cached adjacency lists of safely admitted vertices.

The complete test run passed 1,014 exact `Fraction` cases and three floating diagnostics. It enumerated all 43 connected labeled graphs on 2–4 vertices, with every seed and several rational parameters; additional fixtures were paths, stars, and binary trees. A separate oracle enumerated supports and solved each candidate system by dense rational Gaussian elimination, then checked full KKT conditions. Tests verified the exact objective gap lies below the direct certificate, that the certificate is below the envelope bound and requested tolerance, that every output is coordinatewise below the exact optimum, and that only true-support vertices have adjacency lists scanned.

The degree-100 hub fixture is particularly useful for locality: a leaf seed required exactly one adjacency-entry inspection and two degree replies, while the hub's adjacency list was never scanned. The zero-solution regime required no adjacency inspection. The largest recorded fixture used 22,509 logical work units, 28 CG iterations, and seven restricted solves. These are small-instance measurements, not asymptotic evidence.

The counter ledger explicitly records arithmetic, comparisons, operand/result accesses, persistent map reads and writes, loop events, first graph replies, repeated cached-neighbor reads, CG iterations, boundary tests, and output words. The combined logical work is a word-model accounting up to fixed implementation constants; it is not Python bytecode timing or an exact bit-complexity claim. Fraction numerator growth can make wall-clock arithmetic expensive.

`Fraction` mode provides exact mathematical comparisons and certificates for the supplied rational values. Floating mode recomputes true residuals at candidate termination, but does not bound rounding error and is deliberately labeled diagnostic. Exact sparse output is available in degree coordinates and as radical triples `(i,y_i,d_i)` representing `x_i=y_i sqrt(d_i)`; a consumer wanting floating canonical coordinates can perform that final conversion. No random generator, randomized graph, random pivot, stochastic preconditioner, or randomized solver occurs in the implementation or tests.

The established baseline cumulative bound still includes repeated restricted solves, naively `tilde O(1/(rho² sqrt(alpha)))`. The separately proved accelerated batch-stage analysis can improve the stage accounting with an appropriate stage-limited version, but it does not by itself remove the extra numerical-solve factor. This code intentionally stops on its directly checked objective certificate rather than claiming a conjecture-level total work guarantee.
